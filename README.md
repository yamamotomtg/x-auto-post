# X 定期自動投稿（@mtgkaitori）

お知らせを画面から登録しておくと、その通りに X へ自動投稿します。
お店のPCが消えていても投稿されます。

- 曜日・時刻・期間を自由に指定できます（毎週／毎日／特定の日付）
- **伝える日が祝日・振替休日なら、その投稿だけ自動で見送ります**
- 臨時のお知らせは期間を決めておけば、期間が過ぎると自動で止まります
- 同じ時刻に他のお知らせと重なったときは、登録のときにどちらを優先するか確認します
- 投稿予定の一覧から、**特定の回だけ投稿しない**ようにもできます

## 仕組みの全体像

| 役割 | 担当 |
|---|---|
| お知らせの編集 | **管理画面**（このPCで動かします） |
| お知らせの保管 | **GitHub**（`schedule.yml` と画像） |
| 時刻どおりの投稿 | **Cloudflare**（1分ごとに確認し、時刻になったら投稿） |
| 投稿漏れの見張り | **GitHub Actions**（1日2回、X を見て確認。漏れていればメール） |

管理画面で編集 →「GitHubへ反映」を押す → Cloudflare が新しい内容を読み取って投稿します。
Cloudflare 側の操作は、最初の設置以外では不要です。

> 以前は GitHub だけで投稿していましたが、GitHub の定期実行は2〜5時間遅れることがあり、
> 時刻を決めた告知には使えませんでした。そのため投稿の実行だけ Cloudflare に移しています。

## 使い方

### 管理画面を開く

デスクトップの **「X自動投稿 管理画面」** をダブルクリックします（または
フォルダ内の `管理画面をひらく.cmd`）。黒いウィンドウが開き、ブラウザに画面が出ます。
終わるときは黒いウィンドウを閉じてください。

### お知らせを登録する

1. **＋ 新しいお知らせ** を押す
2. **どんなお知らせか**（名前と、ずっと続けるか期間を決めるか）
3. **いつ投稿するか**（毎週/毎日/日付、時刻、当日のことか翌日のことか、祝日は休むか）
4. **投稿する内容**（文章と画像。「日付を入れる」で対象日の日付が入ります）
5. **確認**（投稿予定と重なりを確認。不要な回はここで外せます）

登録しただけでは反映されません。右上の **GitHubへ反映** を押すと実際の投稿に反映されます。

### 画面でできること

| やりたいこと | 場所 |
|---|---|
| これからの投稿を確認する | 「投稿予定」（70日先まで） |
| 特定の回だけ投稿しない | 「投稿予定」→ その回の「この回は投稿しない」 |
| 文章や時刻を直す | 「お知らせ一覧」→ 編集 |
| お知らせをやめる | 「お知らせ一覧」→ 削除 |

## 設置のしかた

### 1. X のアプリ（済み）

Developer Console でアプリを作り、権限を「読み取りと書き込み」にしてから
アクセストークンを発行します。4つのキーを使います。

### 2. GitHub（済み）

<https://github.com/yamamotomtg/x-auto-post>（公開）。
Settings → Secrets に4つのキーを登録済み（投稿漏れの点検で使います）。

### 3. Cloudflare（投稿の実行・済み）

無料アカウントを作り、このフォルダで次を順に実行しました（作り直すときの手順です）。
（PowerShell では `npx` ではなく **`npx.cmd`** と打ちます。`npx` のままだと「スクリプトの実行が無効」と出ます）

```bash
npx.cmd wrangler login
```

```bash
npx.cmd wrangler deploy
```

```bash
npx.cmd wrangler secret put X_API_KEY
```

`X_API_SECRET` `X_ACCESS_TOKEN` `X_ACCESS_TOKEN_SECRET` も同じように登録します（4回）。
登録後、もう一度 `npx.cmd wrangler deploy` を実行してください。

設置済みです。確認用ページ: <https://x-auto-post.tokyomtgkaitori.workers.dev>
ブラウザで開くと**今後2週間の投稿予定**が表示され、Cloudflare が正しく読み取れているか確認できます。

## 困ったときに

- **投稿されていない** → <https://github.com/yamamotomtg/x-auto-post/actions> の
  「自動投稿」から手動投稿できます（Run workflow → dry_run のチェックを外す → force にチェック）。
  いまの時刻に一番近い回が投稿されます
- **投稿漏れのメールが届いた** → 上の手順で手動投稿してください
- **Cloudflare の動きを見たい** → `npx.cmd wrangler tail`（実行中のログが流れます）
- **一時的に全部止めたい** → `npx.cmd wrangler delete`（復旧は `npx.cmd wrangler deploy`）
- **X のクレジット残高** → <https://developer.x.com> の「使用状況」

## ファイルの説明

| ファイル | 内容 |
|---|---|
| `schedule.yml` | 登録したお知らせ（画面から書き換えられます） |
| `images/` | 投稿に添付する画像 |
| `app/` | 管理画面（サーバーと画面） |
| `worker.mjs` / `wrangler.toml` | Cloudflare で動く投稿処理 |
| `rules.mjs` | お知らせの読み取りと、投稿予定の組み立て |
| `schedule-core.mjs` | 「いま投稿すべきか」「投稿漏れはないか」の判定 |
| `x-api.mjs` | X API の呼び出し（署名・投稿・画像） |
| `post.mjs` | 手動投稿と、投稿漏れの点検（GitHub Actions 用） |
| `build.mjs` | 設定の点検（`node build.mjs --preview` で予定を表示） |
| `holidays.mjs` | 祝日の計算 |
| `test.mjs` | 仕組み全体の点検（`node test.mjs`） |
