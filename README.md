# X 定期自動投稿（@mtgkaitori）

お知らせを画面から登録しておくと、その通りに X へ自動投稿します。
投稿そのものは GitHub のクラウドで動くので、**お店のPCが消えていても投稿されます。**

- 曜日・時刻・期間を自由に指定できます（毎週／毎日／特定の日付）
- **伝える日が祝日・振替休日なら、その投稿だけ自動で見送ります**
- 臨時のお知らせは期間を決めておけば、期間が過ぎると自動で止まります
- 同じ時刻に他のお知らせと重なったときは、登録のときにどちらを優先するか確認します

## 使い方

### 管理画面を開く

フォルダの中の **`管理画面をひらく.cmd` をダブルクリック**します。
黒いウィンドウが開き、ブラウザで <http://localhost:8787> が開きます。このPCの中だけで動く画面です。

終わるときは、黒いウィンドウを閉じるか、そのウィンドウで Ctrl+C を押します。

> コマンドで動かす場合は、このフォルダに移動して `node app/server.mjs` を実行します。
> PowerShell では `npm start` が「スクリプトの実行が無効」と出て止まることがあります
> （Windows の既定の設定によるものです）。その場合は `npm.cmd start` か、上の `node app/server.mjs` を使ってください。

### お知らせを登録する

1. **＋ 新しいお知らせ** を押す
2. **どんなお知らせか**（名前と、ずっと続けるか期間を決めるか）
3. **いつ投稿するか**（毎週/毎日/日付、時刻、当日のことか翌日のことか、祝日は休むか）
4. **投稿する内容**（文章と画像。「日付を入れる」を押すと、対象日の日付が入ります）
5. **確認**（最初の投稿予定と、他のお知らせとの重なりを確認して登録）

登録しただけでは、まだ実際の投稿には反映されません。
右上の **GitHubへ反映** を押すと反映されます。

### 画面でできること

| やりたいこと | 場所 |
|---|---|
| これからの投稿を確認する | 「投稿予定」（70日先まで。祝日で見送るものは薄く表示） |
| 文章や時刻を直す | 「お知らせ一覧」→ 編集 |
| お知らせをやめる | 「お知らせ一覧」→ 削除 |
| 画像を追加する | 登録の手順3で「画像を追加」 |

## はじめの設定

### 1. X のアプリを用意する

[Developer Console](https://developer.x.com) → **アプリ** で、この用途専用のアプリを作ります（例: `monday-hours-post`）。

1. **設定 → ユーザー認証の設定** で、アプリ権限を **「読み取りと書き込み」** にする
2. そのあとで **キーとトークン** を開き、**アクセストークンを発行**する
   （権限を変えた後に発行しないと、投稿が 403 で失敗します）
3. 発行は **@mtgkaitori でログインした状態**で行う

### 2. GitHub にアップロードする

**Private** のリポジトリを作ります（Public にすると、60日間更新がないとスケジュールが止まります）。
このフォルダはすでに git で管理されているので、GitHub でリポジトリを作ったあと次を実行します。

```bash
git remote add origin https://github.com/<ユーザー名>/x-auto-post.git
git push -u origin main
```

以降は、管理画面の **GitHubへ反映** ボタンだけで更新できます。

### 3. キーを登録する

リポジトリの **Settings → Secrets and variables → Actions → New repository secret** で4つ登録します。

| Name | 値 |
|---|---|
| `X_API_KEY` | API Key |
| `X_API_SECRET` | API Key Secret |
| `X_ACCESS_TOKEN` | Access Token |
| `X_ACCESS_TOKEN_SECRET` | Access Token Secret |

### 4. 試運転

**Actions → 自動投稿 → Run workflow**（`dry_run` にチェックが入ったまま）で実行します。
ログに投稿予定の本文と `X API の認証OK: @mtgkaitori として投稿されます` が出れば準備完了です。

実際に投稿まで試すときは `dry_run` のチェックを外します（すぐ投稿されるので、テスト投稿は X から削除してください）。

## 運用メモ

- **投稿が遅れる場合があります**：投稿時刻の10分前に起動して時刻ちょうどまで待ちますが、GitHub が混雑していると数分〜数十分遅れることがあります。45分以上遅れた場合は、その回を見送ります
- **一時的に全部止める**：Actions → 自動投稿 → 右上の「…」→ Disable workflow
- **投稿に失敗したとき**：GitHub からメールが届きます。Actions のログにエラー内容が出ます
- **毎朝9時の自動点検**：設定の食い違いがあれば、ここで気づけるようになっています
- **費用**：X API はクレジット制です。Developer Console の「使用状況」で残高を確認してください。GitHub Actions は Private リポジトリでも月2,000分まで無料です

## ファイルの説明

| ファイル | 内容 |
|---|---|
| `schedule.yml` | 登録したお知らせ（画面から書き換えられます） |
| `images/` | 投稿に添付する画像 |
| `app/` | 管理画面（サーバーと画面） |
| `post.mjs` | 投稿の実行 |
| `rules.mjs` | お知らせの読み取りと、投稿予定の組み立て |
| `build.mjs` | 点検と、GitHub の実行時刻の作り直し |
| `holidays.mjs` | 祝日の計算 |
| `test.mjs` | 仕組み全体の点検（`node test.mjs`） |

`schedule.yml` を手で直すこともできます。その場合は `node build.mjs` を実行してください（実行時刻の設定を作り直します）。
