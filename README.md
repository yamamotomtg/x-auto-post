# X 定期自動投稿（@mtgkaitori）

`schedule.yml` に「いつ・何を投稿するか」を書いておくと、その通りに X へ自動投稿します。
GitHub Actions（GitHub の無料のクラウド実行環境）で動くので、店舗のPCが消えていても投稿されます。

- 曜日・時刻・期間を自由に指定できます（毎週／毎日／特定の日付）
- **対象日が祝日・振替休日なら、その投稿だけ自動で見送ります**
- 臨時のお知らせは「期間」を書いておけば、その週だけ有効になって自動で元に戻ります
- 通常ルールと臨時ルールが同じ時刻に重なったときは、「優先: 高」を書いた方だけ投稿します

## フォルダの中身

| ファイル | 内容 |
|---|---|
| `schedule.yml` | **投稿ルール。普段はここだけ編集します** |
| `images/` | 投稿に添付する画像を置く場所 |
| `build.mjs` | ルールの点検と、実行時刻（cron）の作り直し |
| `post.mjs` | 投稿の実行 |
| `rules.mjs` | ルールの読み取りと展開 |
| `holidays.mjs` | 祝日の計算 |
| `test.mjs` | 仕組み全体の点検 |

## ルールの書き方

```yaml
- 名前: 月曜の買取受付（通常）
  祝日なら休む: はい          # 対象日が祝日なら、その投稿をしない
  画像: monday-hours.jpg      # images/ の中のファイル名。不要なら書かない
  投稿:
    - 日時: 日 21:00          # 毎週日曜の21時
      対象日: 翌日            # 本文の {{対象日}} は翌日（月曜）の日付になる
      本文: |
        【明日{{対象日}}の買取受付につきまして】
        ……
```

| 項目 | 書き方 |
|---|---|
| `日時` | `毎日 10:00` / `日 21:00` / `月 11:00` / `2026-11-03 10:00` |
| `対象日` | `当日`（省略時）または `翌日` |
| `{{対象日}}` | 「11月2日(月)」のような文字に置き換わります |
| `祝日なら休む` | `はい` / `いいえ`（省略時はいいえ） |
| `期間` | `2026-11-02 〜 2026-11-08`。省略するとずっと有効 |
| `優先` | `高` を書くと、同じ時刻に重なった他のルールを見送らせます |

**ルールを書き換えたら、必ず次を実行してください。**実行時刻の設定を作り直します。

```bash
node build.mjs
```

確認だけしたいときは `node build.mjs --preview`（今後70日の投稿予定を表示）です。

## 設置のしかた

### 1. X のアプリを用意する

[Developer Console](https://developer.x.com) → **アプリ** で、この用途専用のアプリを新しく作ります（例: `monday-hours-post`）。

1. **設定 → ユーザー認証の設定** で、アプリ権限を **「読み取りと書き込み」** にする
2. そのあとで **キーとトークン** を開き、**アクセストークンを発行**する
   （権限を変えた後に発行しないと、投稿が 403 で失敗します）
3. 発行は **@mtgkaitori でログインした状態**で行う

### 2. GitHub にアップロードする

**Private** のリポジトリを作り、このフォルダの中身を入れます（Public にすると、60日間更新がないとスケジュールが止まります）。

```bash
git init -b main
git add .
git commit -m "X 定期自動投稿"
git remote add origin https://github.com/<ユーザー名>/x-auto-post.git
git push -u origin main
```

### 3. キーを登録する

リポジトリの **Settings → Secrets and variables → Actions → New repository secret** で4つ登録します。

| Name | 値 |
|---|---|
| `X_API_KEY` | API Key |
| `X_API_SECRET` | API Key Secret |
| `X_ACCESS_TOKEN` | Access Token |
| `X_ACCESS_TOKEN_SECRET` | Access Token Secret |

### 4. 試運転

**Actions → 自動投稿 → Run workflow**（`dry_run` にチェックが入ったまま）で実行します。
ログに投稿予定の本文と `X API の認証OK: @mtgkaitori として投稿されます` が出れば準備完了です。

実際に投稿まで試すときは `dry_run` のチェックを外します（すぐ投稿されるので、テスト投稿は X から削除してください）。

## 運用メモ

- **投稿が遅れる場合があります**：投稿時刻の10分前に起動して時刻ちょうどまで待ちますが、GitHub が混雑していると数分〜数十分遅れることがあります。45分以上遅れた場合は、その回を見送ります
- **一時的に止める**：Actions → 自動投稿 → 右上の「…」→ Disable workflow
- **投稿に失敗したとき**：GitHub からメールが届きます。Actions のログに X からのエラー内容が出ます
- **毎朝9時の自動点検**：`schedule.yml` を直して `node build.mjs` を忘れていると、ここで失敗してメールが届きます
- **費用**：X API はクレジット制です。Developer Console の「使用状況」で残高を確認してください。GitHub Actions は Private リポジトリでも月2,000分まで無料で、この仕組みは1回あたり1〜12分程度です
